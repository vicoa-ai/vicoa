# Vicoa CLI

### v1.9.15
11 November, 2026
- Codex, Pi and Antigravity sessions are now titled from your first message, the way Claude Code sessions are, instead of every one being named "Codex", "Pi" or "Antigravity"
- Session titles are written in the language of your own message. An English message is no longer titled in Spanish or German, a question after a pasted email follows your language rather than the email's, and a forked session is titled from the new message instead of the history it carries
- A plugin can ship a page of its own that opens inside the app and reaches Vicoa only through what its `plugin.json` declares; `vicoa plugin init --template page` scaffolds one
- Develop a plugin without reinstalling it: `vicoa plugin link ./my-plugin` uses the directory in place, `vicoa plugin reload <id>` makes open apps pick up changes, and `vicoa plugin logs <id>` prints its log
- A plugin page can read files only from the places its `plugin.json` names, and never from `~/.vicoa`, `~/.ssh` or other credential folders
- Remove the plugin sidebar `rpc` action, which could call any daemon method; a plugin whose manifest changed after you trusted it now has to be trusted again

### v1.9.14
2 November, 2026
- A new worktree started without a typed name is now named from your first prompt, and its session opens already titled, instead of getting a random pair of words. If the name takes longer than a second, or the server has no model to ask, you get a random name as before
- Random worktree names draw from a larger word list and skip names already taken, so a `-2` suffix only appears once every combination is in use
- Fix a worktree showing an old merged pull request after its new work was pushed under a different branch name, and stop pull requests opened from forks showing on your repo's branches
- When your plan's limit on connected computers is reached, `vicoa` says so and prints where to upgrade; the agent still runs and reaches the app, and the daemon is no longer restarted on every command only to be refused again
- Creating an automation from the CLI now counts against your plan's automation limit, the same as in the app, and a refusal says what is using the allowance

### v1.9.13
29 October, 2026
- Add Claude Sonnet 5.5 to the model picker and drop duplicate 1M-context model entries
- Fix slash command and skill sync failing when a file such as `SKILL.md` isn't valid UTF-8 text, which corrupted the whole sync and dropped every command for that agent
- Send AskUserQuestion option previews (drafts, mockups, snippets) through to the dashboard and app, instead of dropping them when Claude draws them in its own side-by-side box

### v1.9.12
28 October, 2026
- `vicoa task ls --label a,b` keeps tasks that carry any of those labels; repeated `--label` flags still all have to match, so `--label growth --label bug,docs` is growth plus either bug or docs
- Fix starting a session with a long prompt failing with a server error
- Fix `vicoa session start --agent-profile` starting a session without the saved agent's instructions; the session now runs that agent and records it
- Search finds a task by its identifier, such as `VIC-42`, and shows the identifier next to each task it returns

### v1.9.11
8 October, 2026
- `vicoa automation create|update --session <id>` runs an automation in one of your existing sessions instead of starting a new one each time, and `--session none` goes back to a new session per run; the session brings its own machine, folder and agent, so flags that set those are refused next to it
- An automation that runs in a session sends each prompt as a message, or resumes the session with it when it has stopped; a run is skipped while the previous prompt is still waiting, and the automation pauses once its session is gone
- A task status set in the app or with `vicoa task update` now stays put when its linked session starts, ends or is reviewed, so an agent that marks its task blocked and exits leaves it blocked
- `vicoa task create`, `update` and `comment` run inside a Vicoa session record that session, so the task page shows which session created the task and which one each comment or change came from

### v1.9.10
8 October, 2026
- `vicoa session update --project <key|name|none>` moves a session to another of your projects, or to No project; moving it into an archived project brings that project back, and an older server that ignores the move is reported instead of passing silently
- A session moved to another project regroups in every open app at once, without a reload
- Find a task by its identifier after `#`, such as `#VIC-42`, in the session composer and the new session prompt; a full identifier puts that task first even when it is done, and a partial one like `vic-4` narrows the list to that project's tasks
- Fix replacing a project's uploaded icon with another sometimes leaving the old image showing

### v1.9.9
6 October, 2026
- `vicoa automation create|update --agent-profile NAME` links an automation to a saved agent, and `--agent-profile none` unlinks it; a linked automation runs the agent's own config, so session flags passed next to it are refused instead of silently ignored
- Fix an automation linked to a saved agent starting what looked like a plain session: the session now names the agent, shows in its run history, and the agent signs its task comments. Run now in the app also uses the agent's instructions
- `vicoa task create|update --description -` reads the description from stdin, like `task comment -`, instead of saving a literal "-"
- Share a project's automations along with its tasks and sessions; the people you share with see them read-only
- Automations keep the order you drag them into in the app, and `vicoa automation ls` and the mobile app list them the same way; each person's order is their own
- Fix a project someone shared with you pulling in your own sessions from the same repository, where its owner could read and prompt them; it now takes them only once you add it to your sidebar
- Fix restarting the desktop app ending a running session whose prompt mentioned the daemon, which then showed as finished; `vicoa stop daemon` no longer mistakes such a session for the daemon either
- Fix worktree setup commands picking up the system `python3` and missing your shell's tools on macOS; they now run in the daemon's own environment
- A share link's page lists its sessions by latest activity and can filter them by status
- Harden the daemon: it refuses a git ref starting with `-`, and its local server rejects connections opened from a website other than its own local page

### v1.9.5
24 September, 2026
- Fix a session started with `vicoa session start`, or by another agent, never being linked to a machine — which left it without a terminal, a Changes or files panel, a branch badge or file search, for the life of the session; the link is now stamped when the session is staged, and the daemon fills in a missing one when the session registers, so sessions staged by an older client are covered too

- The `vicoa-cli` agent skill now ships with the CLI in `skills/`, so a coding agent can be taught to drive Vicoa from the repo itself; it covers `session start|share|unshare`, the project and label groups, task labels and `worktree setup`, with install notes for Claude Code and other agents in `skills/README.md`

### v1.9.4
22 September, 2026
- `vicoa project ls|get` and `vicoa label ls|create` — your projects and your label vocabulary are finally readable from the terminal, with open-task counts and the same colours the app picks
- `--project` takes a key (`VIC`), a name, or `none` for No project, not just a UUID — on `task ls|create|update` and `agent add`; an ambiguous name lists the candidates instead of guessing, and `task ls` now shows a PROJECT column
- Filter and edit labels from the CLI: `task ls --label` (repeatable, matching all of them), and `--label` / `--add-label` / `--remove-label` on create and update
- `task update` takes several tasks at once, so a bulk move or re-label is one command instead of a shell loop — a ref that fails is reported and the rest still run, and a task that moved projects prints its new identifier (VIC-20 becomes VIC2-2)
- `vicoa session share [ID]` prints just the URL, ready to paste into a `gh pr` command — it defaults to the session it is running in and reuses an equivalent live link unless you pass `--new`; `vicoa session unshare --link|--all` revokes
- `vicoa session ls --since WHEN --until WHEN` asks for the sessions started in a window — a date, a datetime, `today`/`yesterday`, or an age like `30m`/`24h`/`7d` — and `--offset` pages past the first 100
- Fix a share link that opted into showing your name drawing an initials disc instead of your picture, and every other face on a shared board — assignees, comment authors and reactors — doing the same

### v1.9.3
21 September, 2026
- `vicoa session update <id> --worktree <branch>` re-files a session under another checkout of its repo — the worktree that has `<branch>` checked out, or the main checkout's own branch to move it back; the running agent stays where it is, only where the session is listed and where it next resumes changes. A session started in a subfolder lands in the same subfolder of the target
- Deleting a worktree now returns in well under a second — the daemon moves it to a trash folder beside the worktrees and reclaims the files in the background, finishing any leftovers when it next starts; an un-forced delete still refuses a dirty tree or submodules the way git does
- OpenCode and other ACP agents' file edits now show as one card with the path and diff, like Claude Code's, instead of a bare "Edit" card followed by one named after the file; a shell command is carded as soon as it is named, before it finishes
- Fix search failing with "Search failed" for any query that matched a task under "No project" (web and mobile)

### v1.9.1
16 September, 2026
- Add Google's Antigravity CLI (`agy`, 1.1.15 or newer) as an agent — start and resume sessions, pick a model (each Antigravity model id already carries its effort), switch model or permission mode mid-session, and see its tool calls and token usage as they happen; an action the current permission mode doesn't allow ends the turn with a notice on how to unblock it, since headless agy cannot ask

- Fix sessions failing to start with "Headless Claude encountered a fatal error" when the server is slow — registration now retries for up to 20 seconds, the app waits for the session to actually exist before opening it, and a start that still fails reports why instead of leaving an empty session behind
- Sessions and machines are now shown live from their connection to the server rather than from a 30-second poll, and heartbeats cost the server a fraction of what they did — the load that pushed it into CPU throttling on 14 September is gone
